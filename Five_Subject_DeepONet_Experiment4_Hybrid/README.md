# Experiment 4 — Model D: hybrid real + subject-PINN DeepONet

## Purpose

This experiment combines the two training sources tested separately by Models B
and C:

- real trajectories from the three training subjects; and
- 100 synthetic trajectories from each of those same subjects' selected PINN
  teachers.

It asks:

> Are real human trajectories and subject-PINN synthetic trajectories
> complementary when they train one physics-informed DeepONet?

Model D is a secondary experiment. B versus C answers whether real-only or
synthetic-only physics training is better. D determines whether using both
sources is better than either source alone.

## Shared architecture

The architecture preserves the Experiment 1 design:

- four convolutional context windows;
- a four-gain controller head;
- demographics and initial-state conditioning;
- branch and Fourier-time trunk networks;
- branch/trunk latent multiplication;
- GELU activations; and
- hard initial position and velocity constraints.

The controller head uses a positive transformation and returns effective
`Kp_theta`, `Kd_theta`, `Kp_x`, and `Kd_x` values.

## Hybrid training batches

Each optimization step receives:

1. one batch of real trajectories from the three training subjects; and
2. one batch of synthetic trajectories from the same three subjects' PINN
   teachers.

The real loader cycles when necessary because there are many more synthetic
trajectories. The two source losses are weighted equally:

```text
L_D = 0.50 * L_real_part + 0.50 * L_synthetic_part
```

The real part is:

```text
L_real_part = L_real_forecast + 0.01 * L_physics_real
```

The synthetic part is:

```text
L_synthetic_part =
    L_synthetic_trajectory
  + 0.30 * L_teacher_gain_NLL
  + 0.50 * L_inferred_gain_consistency
  + 0.01 * L_physics_synthetic
```

Teacher-gain supervision is applied only to synthetic samples. Real samples do
not have ground-truth gains.

## How physics enters Model D

Physics is present through two routes:

1. **Indirectly:** the synthetic trajectories were generated by subject-specific
   physics-informed teacher models.
2. **Directly:** `physics_residual_loss()` explicitly evaluates the delayed
   cart-pole equations on the DeepONet outputs and participates in
   backpropagation.

For real samples, the residual uses the context-inferred gains. For synthetic
samples, it uses the known teacher gain tuple in the teacher-conditioned forward
path, matching the distillation design.

## Leakage prevention

The five teacher datasets are exported once for efficiency, but a fold loader
selects only the teachers belonging to its three training subjects. Synthetic
data from the validation and test subjects are never loaded into that fold's
training set.

The real validation subject selects the checkpoint. The real test subject is
evaluated only after checkpoint restoration.

## Step-by-step run

### 1. Install dependencies

```bash
cd Five_Subject_DeepONet_Experiment4_Hybrid
chmod +x run_on_mac.sh
./run_on_mac.sh setup
```

The runner activates the existing home environment with:

```bash
source ~/.venv/bin/activate
```

### 2. Validate data, teachers, and folds

```bash
./run_on_mac.sh validate
```

Validation checks the five real-data inventories, exact teacher paths and chunk
numbers, exclusion of the reference gain endpoints, and subject separation in
every fold.

### 3. Run unit and syntax tests

```bash
./run_on_mac.sh test
```

### 4. Run the smoke test

```bash
./run_on_mac.sh smoke
```

The smoke test exports four short trajectories per teacher, prepares short real
arrays, and trains fold 1 for three epochs. It checks both source loaders, MPS,
the explicit physics gradient, validation checkpoint selection, test evaluation,
and plotting. It is not included in the scientific analysis.

### 5. Prepare full real and synthetic data

```bash
./run_on_mac.sh prepare
```

This exports 100 matched three-second trajectories from each selected teacher
and prepares the real A11 trajectories at 100 Hz. All teachers receive the same
100 initial conditions.

### 6. Optionally run one fold

```bash
./run_on_mac.sh fold 1
```

### 7. Run all five folds

```bash
./run_on_mac.sh full
```

The full command trains five independent hybrid models, aggregates the unseen
real-subject results, and creates:

```text
Five_Subject_DeepONet_Experiment4_Results.zip
```

Terminal output is streamed and saved under `results/logs/`.

### 8. Compare all four models after every experiment finishes

If the four experiment directories are siblings with their full results in
place, run:

```bash
./run_on_mac.sh compare
```

This reads the paired per-subject CSVs from Models A, B, C, and D and creates
`results/four_model_comparison/` with a combined CSV, JSON summary, and grouped
comparison plot. Experiment 1 uses its `deeponet_*` columns; Experiments 2–4 use
their common `model_*` columns. Custom result locations can be passed directly
to `compare_four_models.py`.

## MPS support

PyTorch selects MPS first, then CUDA, then CPU, with MPS fallback enabled. The
TensorFlow portion only loads the Keras teachers and exports trajectories. If
`tensorflow-metal` is already installed it may be used automatically, but it is
not required.

To force CPU for one diagnostic fold:

```bash
source ~/.venv/bin/activate
python -u train_fold.py --mode full --fold 1 --device cpu
```

## Completed full-run and four-model result

All five hybrid folds and the A/B/C/D comparison completed. Model D improved
substantially over synthetic-only Model C, but it did not outperform direct
real+physics Model B.

| Model | Normalized MSE | Theta RMSE (deg) | x RMSE (cm) |
|:---|---:|---:|---:|
| A — real data-only | 0.408 | 7.636 | 13.362 |
| **B — direct real + physics** | **0.234** | **6.844** | **9.808** |
| C — subject-PINN distillation | 0.778 | 11.620 | 16.379 |
| D — hybrid | 0.474 | 7.333 | 14.337 |

Relative to C, D reduced normalized MSE by 39.09%, theta RMSE by 36.89%, and
x RMSE by 12.47%. Relative to B, however, D was worse by 50.71% in normalized
MSE, 6.67% in theta RMSE, and 31.59% in x RMSE. S57 remained the decisive hybrid
failure: normalized MSE 1.212 and x RMSE 23.798 cm.

The main result is therefore that real trajectories and explicit physics worked
best when trained directly. Adding the current synthetic-teacher objective did
not improve the direct model and reintroduced synthetic-to-real instability.
See `FINDINGS.md` for all seven metrics, subject-level tables, gain diagnostics,
and interpretation limits.

## Four-model interpretation

| Comparison | Interpretation |
|:---|:---|
| A vs B | Does explicit physics help direct real training? |
| B vs C | Is direct real physics or subject-PINN distillation better? |
| D vs B | Does adding synthetic teacher data help a direct real physics model? |
| D vs C | Does adding real trajectories reduce the synthetic-to-real gap? |

If D performs best, the conclusion is that the sources are complementary—not
that either synthetic-only or real-only training is independently superior.
